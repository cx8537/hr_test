# 10. 비기능 요구사항 (NFR)

보안·성능·운영·확장성 등 시스템 전반 요건. 모듈 코드: **NFR**

---

## 1. 보안 (Security)

### NFR-SEC-001 인증·세션
- **Access(짧은 수명) + Refresh 토큰** 기반(FND-003). Access 토큰에는 **사용자 식별자·만료만** 담고, 역할은 매 요청 서버 조회·판정한다.
- **매 보호 요청마다 계정 활성 상태와 토큰 버전을 검증**해 비활성·퇴사·로그아웃·강제만료를 즉시 차단한다(FND-004). 만료를 기다리지 않는다.
- 비밀번호는 BCrypt 등 단방향 해시로 저장. 평문·가역 암호 금지.
- 비밀번호 정책: 8자 이상, 영문+숫자. (기본 수준)

### NFR-SEC-002 계정 보호
- 로그인 실패 누적 시 계정 잠금(예: 연속 N회 실패 시 일정 시간 잠금) — 임계값은 설정 가능.
- **비밀번호 재설정은 시스템관리자 주도 리셋**(임시 비밀번호 발급 → 최초 로그인 시 변경 강제). 외부 이메일을 쓰지 않으므로(NOTI-001) 본인 셀프 재설정 링크는 제공하지 않는다.

### NFR-SEC-003 결재 키·서명
- 개인키는 서버에 저장하지 않는다(공개키만). 서명은 브라우저 Web Crypto(RSA-2048).
- 서명마다 사용 공개키 ID 기록. 폐기 키도 검증용 보존.
- 서명 대상 데이터(문서 핵심 필드)의 정규화 방식을 프론트·백엔드가 동일하게 정의해 서명 불일치를 방지한다.

### NFR-SEC-004 권한 강제(서버 측)
- 모든 권한 검사는 **백엔드 API에서 강제**한다. 프론트 화면 숨김·라우트 가드(FND-010)는 UX·실수 방지용 보조일 뿐 신뢰 경계가 아니다. CSR 구조상 관리자 페이지 코드가 클라이언트 번들에 포함되더라도 민감 데이터·동작은 API 권한 검사로만 통제된다.
- RBAC + 범위(Scope) 기반(FND-006). 권한 없는 요청은 403. 역할은 토큰이 아니라 매 요청 서버 조회로 판정(권한 변경 즉시 반영).

### NFR-SEC-005 파일 접근
- MinIO 파일은 **백엔드 경유**로만 접근(권한 검사 후 전달). presigned URL·직접 노출 금지.
- 민감 양식·반려/회수 문서는 관여자 한정(DOC-005)을 다운로드까지 강제.

### NFR-SEC-006 전송·입력 보안
- 운영 시 HTTPS 적용(개발 환경 제외).
- 입력 검증(서버 측 필수): SQL Injection 방지(파라미터 바인딩/JPA), XSS 방지(출력 인코딩), 파일 업로드 검증(확장자·MIME·크기).
- CSRF: 토큰 기반 인증 + 적절한 헤더 정책으로 대응.

### NFR-SEC-007 감사 로그(Audit)
- **대부분의 변경 이력을 전수 기록**: 생성·수정·삭제(비활성화)·결재 행위·권한 변경·키 폐기/재발급·예약 취소 등.
- 각 로그: 행위자, 시각, 대상, 행위 종류, 변경 요약.
- 감사 로그는 무기한 보관, **append-only 강제**: 수정·삭제 API를 제공하지 않는다(가능 시 DB 권한으로 UPDATE/DELETE 차단 병행).
- 조회는 **시스템관리자 전용 화면**에서만 제공한다(일반 사용자 노출 금지).

## 2. 성능 (Performance)

### NFR-PERF-001 응답 시간(목표)
- 일반 조회 API: 통상 1초 이내 응답(사내 규모 기준).
- 목록·검색: 페이지네이션 적용(대량 데이터에서도 일정 응답성 유지).
- 매 요청 계정상태·역할 조회(NFR-SEC-001)와 알림 뱃지 폴링(NOTI-003, 30~60초)이 추가되나 사내 규모에서는 부담이 작다. 필요 시 단기 캐시·인덱스로 흡수한다.

### NFR-PERF-002 인덱싱
- 고빈도 조회 컬럼에 인덱스: 로그인 ID, 사번, 부서코드, 거점코드, 비품 관리번호, 예약(자원ID+시간대), 문서(제목·폴더·태그), 알림(수신자+읽음상태).
- 예약 시간 겹침은 **EXCLUSION 제약이 생성하는 GiST 인덱스**(자원ID + tstzrange)로 조회·보장.

### NFR-PERF-003 동시성 (자원별 전략)
- **예약 중복 방지(RSV-003)**: EXCLUSION 제약으로 동시 요청에도 한 건만 성공.
- **결재 상태 전이(AP-033)**: 비관적 락(SELECT FOR UPDATE) + 상태 재검증으로 동시 승인·회수 레이스 차단.
- **일반 편집(거점·비품·자원 등)**: 낙관적 잠금(`version` 컬럼). 버전 불일치 시 거부("다른 사용자가 먼저 수정함").
- **비품 수량 입출고(AST-003)**: 트랜잭션 일관성 보장(동시 출고로 인한 음수 방지).
> 동시성 전략 표는 `09-testing-strategy.md` 참조.

### NFR-PERF-004 파일 처리
- 사진·첨부 업로드/다운로드는 스트리밍 처리로 메모리 부담 최소화.
- 이미지 다수(거점·비품 사진) 조회 시 썸네일·지연 로딩 고려.

### NFR-PERF-005 페이지네이션·목록
- 모든 목록 API는 페이지네이션·정렬·필터를 지원. 무한정 전체 반환 금지.

## 3. 가용성·데이터 (Availability & Data)

### NFR-DATA-001 보존 정책
- 데이터·로그·알림은 **무기한 보관**. 자동 삭제·아카이빙 없음.
- 소프트 삭제(비활성화) 원칙: 사용자·부서·거점·비품(폐기)·공개키는 물리 삭제하지 않는다.

### NFR-DATA-002 백업
- PostgreSQL 정기 백업, MinIO 데이터 정기 백업(운영 환경). 복구 절차 문서화.

### NFR-DATA-003 무결성
- 외래키·유니크 제약으로 참조 무결성 보장.
- 비활성 참조의 신규 선택 차단은 애플리케이션 레벨 + 가능 시 DB 제약 병행.

### NFR-DATA-004 파일↔DB 정합성
- 첨부·사진 업로드는 "MinIO 객체 + DB 메타"의 2단계다. **파일을 먼저 MinIO에 저장하고 성공 시 DB 메타를 커밋**한다(다운로드는 DB 메타 기준이라 객체 고아는 노출되지 않음).
- 업로드 실패로 남은 **미참조 객체·메타는 주기 정리 배치**로 회수한다(object_key의 참조ID로 추적, 일정 시간 경과 고아만 대상). 무기한 보관(NFR-DATA-001) 대상은 정상 파일·버전이며 실패 고아는 정리 대상이다.

## 4. 운영·환경 (Operations)

### NFR-OPS-001 배포 구성
- Docker 미사용. Windows 11에 네이티브 설치: PostgreSQL, JDK 21, Node.js, MinIO(minio.exe).
- 프론트·백엔드 분리 배포. 환경별 설정(개발/운영) 분리.
- **DB 스키마는 Flyway 버전드 마이그레이션으로 관리**(운영 `ddl-auto=validate`). 초기 데이터(최초 시스템관리자 등)도 시드 마이그레이션으로 적재.
- **타임존은 KST(Asia/Seoul) 고정**(서버 JVM·PostgreSQL·브라우저). 휴가 일수·예약 시간·미래 판정의 정확성 확보.

### NFR-OPS-002 설정 외부화
- DB 접속정보, JWT 시크릿, MinIO 자격증명, 지도 API 키, **최초 관리자 초기 비밀번호** 등은 환경변수/설정파일로 외부화(코드 하드코딩 금지).
- 비밀값은 버전관리에 커밋하지 않는다.

### NFR-OPS-003 지도 API
- 국내 지도 API 사용(카카오맵 권장). 핀 드롭·마커 지원. API 키는 프론트 환경변수.
- (네이버맵 대안 가능 — 최종 선택은 키 발급·약관에 따라 결정.)

### NFR-OPS-004 확장 여지(미래)
- 모바일 대응, 외부 알림(이메일), 전결 금액 조건, 연차 자동 차감, 예약 제한값 정책 — 현재 미구현이나 데이터·설정 구조에 확장 여지를 둔다.

### NFR-OPS-005 로깅·모니터링
- 애플리케이션 로그(요청·오류) 기록. 감사 로그와 별개.
- 주요 오류는 추적 가능한 형태(상관관계 ID 등)로 기록.
