# 13. E2E 인수 검증 (시스템 가동 후)

단위·통합 테스트(`09`)가 부품의 정확성을 보장한다면, 이 문서는 **네 프로세스(PostgreSQL·Spring Boot·Next.js·MinIO)가 모두 붙은 상태에서 역할별 사용자가 실제로 일을 끝까지 해내는가, 해선 안 되는 일이 진짜 막히는가**를 브라우저로 검증한다. 특히 권한 경계(FND-006·FND-010·DOC-005·즉시 반영)가 화면·네트워크에서 새지 않는지를 1순위로 본다. 모듈 코드: **E2E**

---

## 1. 방식 (탐색 + 회귀 병행)
- **(a) 에이전트 주도 탐색** — Playwright MCP로 역할 페르소나별 격리 컨텍스트에서 직접 조작·검증(비정형 결함 발견).
- **(b) 코드화된 회귀** — (a)에서 확정한 시나리오를 Playwright 스크립트로 고정해 반복 실행.
- 루프: **탐색(a)으로 찾고 → 코드(b)로 고정하고 → 결함은 단위/통합 테스트로 환원**.

## 2. 도구
- **Playwright MCP**(탐색) + Playwright 코드(회귀). 역할별 브라우저 컨텍스트 격리, 접근성 트리 기반 셀렉터, 네트워크 가로채기(403 확인)에 사용.

## 3. 픽스처 (결정론적 시드)
- 페르소나: `U` 일반사용자(영업부) · `LM` 거점관리자@서울 · `DM` 부서관리자@영업부 · `AM` 비품관리자@서울 · `SA` 시스템관리자
- 데이터: 부서(영업·개발), 거점(서울·부산), 자원(서울-차량1·회의실1), 양식 4종, 공휴일 일부
- **페르소나별 테스트 키페어**: 공개키는 `SignatureKey`로 시드 등록, 개인키 PEM은 픽스처 파일.
- 매 실행 전 **테스트 스키마 초기화 + 시드 + 고정 Clock + KST**. 4프로세스 헬스체크(PostgreSQL/MinIO 버킷/Spring `/health`/Next dev) 그린 확인.

## 4. 서명 키 주입
- 결재 승인 단계에서 자동화가 `persona-keys/<persona>.pkcs8.pem`을 읽어 **Web Crypto import→sign**, 실제 프론트 서명 경로를 그대로 탄다(서명 우회 금지). 공개키는 시드 등록되어 검증 통과(FND-008).

## 6. 판정 기준
- 각 시나리오는 **명시적 기대결과**(상태 전이 / HTTP 코드 / 요소 유무)로 pass/fail. "에러 안 남"은 통과 아님.
- **"거부" 시나리오는 부정 판정 필수** — 정확한 403/차단 확인.
- **권한 경계는 네트워크 레벨까지** — 프론트 숨김만이 아니라, 관리자 API를 일반 토큰으로 직접 호출해 **403**까지 확인(라우트 가드 우회 불가).

## 7. 결함 루프
**발견 → 분류 → 환원 → 고정 → 재검**
- 분류: ① 기능 버그 ② **권한 누수(보안, 최우선)** ③ 명세 모호/충돌 ④ 환경·시드 문제.
- 환원: 재현 가능한 결함은 **가장 낮은 레벨(단위/통합) 테스트로 케이스 추가**해 고정. 권한 누수는 도메인 RBAC 단위테스트 + E2E 양쪽에 박는다.
- ③ 명세 모호는 코드로 임의 해석하지 말고 요구사항 문서 확인·질문(CLAUDE.md 규칙).
- 수정 후 해당 E2E + 환원된 하위 테스트 재실행 → 그린 → 회귀셋 영구 편입.

## 8. 실행 시점·안정성
- 모듈 완성 시(해당 시나리오) + 통합 마일스톤(전체) + 릴리스 전(스모크). "단위·통합 그린 → E2E" 순.
- 고정 sleep 금지 → **조건 대기**(요소/네트워크 idle). 비동기(알림 생성, 자동보관)는 폴링/조건 대기. 컨텍스트 격리로 세션 교차오염 방지.
- 테스트 키페어 등 픽스처는 **테스트 전용**이며 운영과 분리한다(FND-007 개인키 비저장 원칙은 운영에 유지).
