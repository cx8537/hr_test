# 08. 상태 변화·예외 규칙 (LIFE)

정적 등록이 아닌 "변화·예외 상황"의 규칙. 여러 모듈에 걸친다. 모듈 코드: **LIFE**

---

## A. 사람의 변화 (퇴사·이동)

### LIFE-A1 퇴사자 계정
- 계정은 **비활성화**(물리 삭제 금지). 로그인 차단, 과거 데이터 보존.
- **AC1**: 비활성 계정은 로그인 불가, 작성·결재 이력은 조회 가능.

### LIFE-A2 진행 중 결재의 퇴사자
- 퇴사자가 결재선에 포함된 진행 중 문서는 **시스템 관리자가 결재선에서 수동 교체**(자동 우회 없음).
- 퇴사 처리 시, 해당자가 결재선에 포함된 진행 중 문서가 있으면 관리자에게 교체를 요구하는 안내를 표시한다.
- **AC1**: 퇴사 처리 시 해당자가 걸린 진행 중 문서 목록이 관리자에게 제시된다.
- **AC2**: 관리자가 결재자를 교체하면 결재가 정상 진행된다.

### LIFE-A3 퇴사자 결재 키
- 퇴사(비활성화) 시 결재 서명 키를 **자동 폐기**. 단, 폐기된 공개키는 과거 서명 검증용으로 보존(FND-009).
- 키 폐기와 결재선 교체(LIFE-A2)는 함께 처리되어야 결재 정지를 방지한다.
- **AC1**: 퇴사 처리 시 해당자의 공개키 상태가 `폐기`로 바뀐다.
- **AC2**: 폐기 후에도 그가 과거에 한 서명은 검증 가능하다.

### LIFE-A4 부서 이동 시 데이터 귀속
- 이동 **이전** 생성 데이터는 이전 부서 소속으로 그대로 남는다. 이동 **이후** 데이터만 새 부서 귀속.
- **AC1**: 이동 전 결재 문서의 소속 부서는 변경되지 않는다.

### LIFE-A5 시스템관리자 최소 1명 보장
- 시스템관리자가 **0명이 되는 비활성화·권한 회수는 거부**한다(self-lockout 방지).
- **AC1**: 마지막 시스템관리자의 비활성화, 또는 시스템관리자 역할 회수 시도는 거부된다.
- **AC2**: 시스템관리자가 2명 이상이면 그중 한 명의 비활성화·회수는 허용된다.

---

## B. 조직의 변화 (부서 개편)

### LIFE-B1 부서 비활성화
- 부서는 물리 삭제 불가, **비활성화만** 가능. 과거 기록 유지.
- 비활성 부서는 신규 소속·결재선 지정에 사용 불가.
- **AC1**: 비활성 부서는 신규 임직원 소속 지정 선택지에서 제외된다.

### LIFE-B2 비활성화 전 직원 재배치
- 소속 직원이 남아 있으면 부서 비활성화 거부. 직원을 다른 부서로 재배치 후 비활성화.
- **AC1**: 소속 직원이 있는 부서의 비활성화는 거부된다.
- **AC2**: 모든 직원 재배치 후 비활성화가 허용된다.

### LIFE-B3 진행 중 문서의 결재선 유지
- 부서 구조가 바뀌어도 진행 중 문서의 결재선은 상신 시 스냅샷을 유지(재계산 안 함, AP-002).
- **AC1**: 부서 변경 후에도 진행 중 문서 결재선은 불변.

---

## C. 자원의 소멸 (거점·비품·예약 자원)

### LIFE-C1 거점 비활성화(폐쇄)
- 거점은 비활성화만 가능. 비활성화 전 소속 자원(비품·차량·회의실) 정리 필수(이전 또는 폐기/삭제).
- 거점 비활성화 시 영향받는 자원·미래 예약 건수를 **사전 경고**로 표시.
- **AC1**: 소속 자원이 남아 있으면 거점 비활성화 거부.
- **AC2**: 비활성화 직전 영향 건수(자원·미래 예약)가 관리자에게 표시된다.

### LIFE-C2 비품 폐기
- 폐기해도 레코드는 `폐기` 상태로 보존(AST-004). 개체 비품은 과정 이력 없이 현재 상태만.
- **AC1**: 폐기된 비품은 조회 가능하되 신규 사용 대상에서 제외.

### LIFE-C3 예약 자원 삭제 시 미래 예약
- 자원 삭제(비활성화) 시 미래 예약 자동 취소 + 예약자 알림(RSV-007).
- **AC1**: 자원 삭제 시 미래 예약이 모두 취소되고 알림이 발송된다.
- **AC2**: 과거 예약 기록은 보존된다.

---

## D. 결재의 예외 흐름

### LIFE-D1 반려 → 재상신
- 반려 문서는 수정 후 같은 문서로 재상신. 결재선 처음부터 재시작(AP-032). 과거 반려 이력 보존.

### LIFE-D2 반려·회수 문서 보관·공개
- 반려·회수 문서도 아카이브 보관(DOC-002). 공개 범위는 **관여자한정**(DOC-005).

### LIFE-D3 합의 거부 → 보류
- 합의 거부 시 보류(멈춤). 철회 시 재개(AP-013).

---

## 전역 규칙 (요약)
- **신규 선택 불가, 기존 표시 유지**: 비활성 부서·거점·자원은 모든 신규 입력 화면 선택지에서 제외하되, 기존 참조 데이터는 그대로 표시. 이 규칙은 이를 참조하는 모든 화면(비품 수령지, 자원 등록, 결재선, 소속 지정 등)에 일관 적용.

## 모듈화 가이드 (TDD)
- "비활성화 가능 여부 판정"을 각 도메인(부서/거점)에서 순수 함수로 분리(`소속 존재 → 허용/거부`).
- 퇴사 처리는 트랜잭션으로 (계정 비활성 + 키 폐기 + 영향 문서 목록 산출)을 함께 수행. 통합 테스트로 일관성 검증.
