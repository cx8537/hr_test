# 03. 거점 관리 (LOC)

지역 사무소(거점). 비품·예약 자원의 상위 단위. 모듈 코드: **LOC**

---

### LOC-001 거점 등록·관리
거점 속성:
- 거점명, 거점코드(고유), 주소, 좌표(위도/경도), 대표 연락처, 팩스, 거점 담당자(임직원 1명), 거점 유형(본사/지점/창고 등), 사진(다중), 상태(활성/비활성).
- **AC1**: 거점코드는 중복 불가.
- **AC2**: 거점 담당자는 1명만 지정한다.

### LOC-002 좌표 입력 (지도 핀)
- 좌표는 관리자가 **지도에서 핀을 찍어** 지정한다(주소 자동 변환[지오코딩] 사용 안 함).
- 지도는 국내 지도 API(카카오맵/네이버맵 중 택1, `10-nonfunctional.md`에서 확정) 사용. 핀 드롭·마커 표시 지원.
- **AC1**: 핀으로 지정한 위도/경도가 거점에 저장된다.

### LOC-003 담당자와 권한의 분리
- 거점 담당자 지정은 **거점관리자 역할 부여와 별개**다. 담당자로 지정돼도 자동으로 권한이 생기지 않는다.
- 권한은 FND-006에 따라 `(거점관리자, 거점ID)`로 별도 부여.
- **AC1**: 담당자로만 지정된 사용자는 거점 관리 API 호출 시 403(역할 미부여 시).

### LOC-004 거점 사진 (다중)
- 거점당 여러 장의 사진 등록 가능. 저장은 MinIO 경유.
- **AC1**: 한 거점에 2장 이상 사진을 등록·조회할 수 있다.

### LOC-005 거점 현황 화면 (지도/목록 토글)
- 전체 거점을 **지도 뷰**(마커)와 **목록 뷰**로 보여주며 토글 전환.
- **AC1**: 지도 뷰는 모든 활성 거점을 마커로 표시한다.
- **AC2**: 목록 뷰와 지도 뷰는 같은 데이터셋을 보여준다.

### LOC-006 거점 비활성화(폐쇄)
- 거점은 물리 삭제하지 않고 **비활성화**한다. 비활성화 전 소속 자원(비품·차량·회의실) 정리 필수.
- 상세 규칙·연쇄 효과(미래 예약 자동 취소 등)는 `08-lifecycle-rules.md` LIFE-C 참조.
- **AC1**: 소속 자원이 남아 있으면 비활성화가 거부된다.
- **AC2**: 비활성 거점은 신규 참조(비품 수령지·자원 등록 등) 선택지에서 제외된다.

---

## 모듈화 가이드 (TDD)
- `location` 패키지 독립. 거점 CRUD와 비활성화 가능 여부 판정(`소속 자원 존재 여부 → 비활성화 허용/거부`)을 순수 함수로 분리.
- 지도 컴포넌트는 프론트(Next.js)에서 거점 좌표 목록을 받아 렌더. 백엔드는 좌표 데이터만 제공(지도 API 키는 프론트 환경변수).
