# 07. 알림 (NOTI)

시스템 내 알림함만 사용(외부 알림 없음). 모듈 코드: **NOTI**

---

### NOTI-001 알림 채널
- **시스템 내 알림함**에만 알림이 쌓인다. 이메일·SMS 등 외부 발송 없음.
- **AC1**: 알림 생성 시 외부 발송이 일어나지 않는다(알림함 레코드만 생성).

### NOTI-002 알림 발생 이벤트 (목록)
다음 이벤트에서 알림을 생성한다.

**결재 관련**
- 내 결재 차례 도달(결재 요청 도착) — 대상: 해당 결재자.
- 내가 상신한 문서 **승인완료** — 대상: 상신자.
- 내가 상신한 문서 **반려**(사유 포함) — 대상: 상신자.
- 내가 **합의자**로 지정된 문서의 합의 요청 도달 — 대상: 합의자.
- 합의 거부로 인한 **보류** 발생 — 대상: 상신자.
- 내가 **대결 대리인**으로서 처리할 결재 발생 — 대상: 대리인.

**예약 관련**
- 내 예약이 **관리자에 의해 취소**(사유 포함) — 대상: 예약자.
- 내 예약 자원이 **삭제되어 예약 자동 취소** — 대상: 예약자.

**비품 관련**
- 1차 범위에서 일반 사용자 대상 비품 알림 없음.

- **AC1**: 위 각 이벤트 발생 시 지정 대상에게 알림 1건이 생성된다.
- **AC2**: 정상 흐름(전결 생략 단계 등)에는 불필요한 알림을 생성하지 않는다.

### NOTI-003 알림 상태·표시
- 각 알림은 읽음/안읽음 상태를 가진다. 안읽음 개수가 뱃지로 표시된다.
- 뱃지 갱신은 **클라이언트 주기 폴링**(예: 30~60초 간격으로 안읽음 수 조회)으로 한다. 실시간 푸시(SSE/WebSocket)는 1차 범위 외(사내 업무엔 폴링으로 충분).
- 알림 클릭 시 관련 문서·예약 상세로 이동.
- **AC1**: 안읽음 알림 수가 정확히 집계된다.
- **AC2**: 알림을 읽으면 안읽음 카운트가 감소한다.

### NOTI-004 보존
- 알림은 무기한 보관(자동 삭제 없음).

---

## 모듈화 가이드 (TDD)
- `notification` 패키지. 알림 생성은 각 모듈의 도메인 이벤트를 구독하는 핸들러로 구현(모듈 간 직접 호출 대신 이벤트 기반 → 결합도↓, 테스트 용이).
- "이벤트 → 알림 대상·내용" 매핑을 순수 함수로 분리해 표 기반 테스트.
