# 02. 전자결재 (AP)

가장 복잡한 모듈. 결재선·결재 흐름·고급 기능·양식으로 구성. 모듈 코드: **AP**

---

## 1. 결재선

### AP-001 결재선 자동 적용 + 수정
- 부서별로 사전 정의된 **기본 결재선**이 상신 시 자동 적용된다. 상신자는 필요 시 수정할 수 있다.
- **AC1**: 상신 시 상신자 소속 부서의 기본 결재선이 초기값으로 채워진다.
- **AC2**: 상신자는 결재자를 추가·제거·순서변경할 수 있다(단, 전결 규칙 위반은 불가 — AP-020).

### AP-002 결재선 스냅샷 (핵심)
- 상신 시점에 결재선이 **복사·고정**된다. 이후 부서 개편·인사 이동·기본 결재선 변경이 진행 중 문서에 영향을 주지 않는다.
- 단, 스냅샷은 결재선 **구조(누가 어느 단계)**를 고정하는 것이며, **실제 처리 권한은 런타임에 판정**한다: ① 위임/대결(AP-021/022)은 처리 시점에 조회, ② 퇴사자 결재선 교체(LIFE-A2)는 시스템관리자가 스냅샷을 예외적으로 수정.
- **AC1**: 상신 후 기본 결재선을 변경해도 이미 진행 중인 문서의 결재선은 바뀌지 않는다.
- **AC2**: 결재선 스냅샷에는 각 결재자의 식별자·단계·유형(순차/병렬/합의)이 포함된다.
- **AC3**: 위임/대결로 대리 처리해도 스냅샷의 원 결재자 식별자는 보존된다(런타임 처리자와 별개).

## 2. 결재 흐름

### AP-010 순차 결재
- 결재자가 한 명씩 차례로 승인. 앞 단계 승인 후 다음 단계로 진행.
- **AC1**: 1단계 승인 전에는 2단계 결재자가 승인할 수 없다.
- **AC2**: 모든 단계 승인 시 문서는 `승인완료` 상태가 된다.

### AP-011 병렬 결재 (전원 승인)
- 같은 단계의 여러 결재자가 동시에 처리. **전원 승인**해야 다음 단계로 진행.
- **AC1**: 병렬 단계의 결재자 일부만 승인하면 다음 단계로 진행하지 않는다.
- **AC2**: 병렬 단계 전원이 승인하면 다음 단계로 진행한다.

### AP-012 병렬 반려 (즉시 전체 반려)
- 병렬 단계에서 **한 명이라도 반려**하면 그 즉시 전체 문서가 `반려` 상태가 된다.
- **AC1**: 병렬 결재자 중 1인이 반려하면 같은 단계의 나머지 결재 대기 여부와 무관하게 문서는 반려된다.
- **AC2**: 반려 시 반려자·사유가 기록된다(AP-031).

### AP-013 합의 (차단형, 거부 시 보류)
- 합의자는 결재선의 **독립 단계(step)**를 차지한다. 각 단계는 단일 유형(순차/병렬/합의)이며 한 단계에 유형이 혼재하지 않는다. 한 합의 단계에 합의자가 여럿이면 **전원 동의**해야 다음 단계로 진행한다.
- 합의자가 거부하면 문서는 **보류(멈춤)** 상태가 된다. 전체 반려로 즉시 돌아가지 않는다.
- 보류 상태에서: ① 상신자가 회수 가능(AP-030 조건 충족 시), ② 합의자가 거부를 철회하면 진행 재개.
- **AC1**: 합의자 거부 시 문서 상태는 `보류`가 된다(반려 아님).
- **AC2**: 합의자가 거부를 철회하면 보류 직전 상태로 진행이 재개된다.
- **AC3**: 보류 발생 시 상신자에게 알림이 생성된다(NOTI 참조).
- **AC4**: 합의 단계에 합의자가 여럿이면 전원이 동의해야 다음 단계로 진행한다(일부 동의로 진행하지 않음).

## 3. 고급 기능

### AP-020 전결 (문서 종류 기준)
- 각 문서 종류(양식)에 **전결 종료 단계**를 지정한다. 상신 시 결재선은 전결 단계까지만 포함하고 그 위 단계는 자동 생략한다.
- 전결로 생략된 상위 결재자에게는 별도 통보하지 않는다(정상 흐름).
- 금액 조건은 두지 않는다(문서 종류 기준만). 단, 데이터 모델에 금액 조건 컬럼을 확장 여지로 비워둔다(미사용).
- **AC1**: 전결이 지정된 양식은 결재선에서 전결 단계 위가 생략된다.
- **AC2**: 전결자가 승인하면 문서는 `승인완료`가 된다.
- **AC3**: 상신자는 전결 단계를 임의로 넘겨 상위까지 결재선을 늘릴 수 없다.

### AP-021 대결 (사전 지정 대리인)
- 결재자는 자신의 대리인을 **사전 지정**한다. 결재자 부재 시 대리인이 대신 결재한다.
- 대결 적용 여부는 **결재 처리 시점에 런타임으로 판정**한다(스냅샷엔 원 결재자만 고정, AP-002).
- 대결 시 결재 이력에 "○○○를 대신하여 △△△ 대결"로 표시한다. 서명은 **대리인 본인 키**로 한다.
- **AC1**: 대리인은 위임자(결재자) 대신 해당 단계를 승인/반려할 수 있다.
- **AC2**: 대결 처리된 서명은 대리인 본인 공개키로 검증된다.
- **AC3**: 결재 이력에 원 결재자와 실제 대결자가 모두 표시된다.

### AP-022 위임 (위임자 명의 표시 + 수임자 키 서명)
- 위임은 권한을 다른 사람에게 넘기며, **기간 없이 수동 해제**까지 유효하다.
- 위임 적용 여부는 **결재 처리 시점에 런타임으로 조회**한다. 상신 후 설정/해제된 위임도 그 시점의 유효 상태로 반영된다(스냅샷엔 원 결재자만 고정, AP-002).
- 서명은 **수임자(위임받은 사람) 본인 키**로 한다(개인키 공유 금지). 표시는 "위임자 ○○○ (수임자 △△△ 대행)"으로 위임자·수임자를 모두 드러낸다.
- 감사 로그에 실제 서명자(수임자)와 위임 관계를 기록한다.
- **AC1**: 위임이 설정되면 수임자가 위임자의 결재 단계를 처리할 수 있다.
- **AC2**: 위임 결재의 서명은 수임자 공개키로 검증된다.
- **AC3**: 위임은 위임자가 수동 해제하기 전까지 유효하다(자동 만료 없음).
- **AC4**: 문서 표시에 위임자·수임자가 모두 나타난다.

> 대결 vs 위임 차이: 대결=건별 부재 대리(원 결재자 식별 표면화), 위임=기간 단위 권한 이전(위임자 명의 우선 표시). 서명 주체는 둘 다 실제 처리자 본인 키.

## 4. 상태·회수·반려

### AP-030 회수 (상신 취소)
- 상신자는 진행 중 문서를 회수할 수 있으나, 결재자 중 **한 명이라도 승인했으면 회수 불가**.
- **AC1**: 아무도 승인하지 않은 문서는 상신자가 회수할 수 있다(상태 `회수`).
- **AC2**: 한 명이라도 승인한 문서는 회수 시도가 거부된다.

### AP-031 반려 (사유 필수)
- 결재자가 반려할 때 **반려 사유 입력은 필수**다.
- **AC1**: 사유 없이 반려 시도 시 거부된다.
- **AC2**: 반려 시 문서 상태는 `반려`, 반려자·사유·시각이 기록된다.

### AP-032 반려 문서 재상신 (결재선 처음부터)
- 반려된 문서는 상신자가 수정 후 **같은 문서로 재상신**할 수 있다.
- 재상신하면 결재선이 **처음부터 다시 시작**된다. 이전 승인·서명은 무효화된다. 단, 과거 반려 이력은 보존한다.
- 수정 내용은 아카이브 버전 이력으로 남는다(DOC 참조).
- **AC1**: 반려 문서 재상신 시 결재 진행이 1단계부터 재시작된다.
- **AC2**: 이전 라운드의 승인/서명은 현재 라운드 판정에 사용되지 않는다.
- **AC3**: 과거 반려 사유·이력은 조회 가능하게 보존된다.

### AP-033 문서 상태 일람
`임시저장` → `진행중` → (`보류`) → `승인완료` | `반려` | `회수`
- 상태 전이는 **동시성 제어**가 필요하다. 결재 처리 시 문서 행을 **비관적 락(SELECT FOR UPDATE)**으로 잠근 뒤 현재 상태를 재검증하고 전이한다(동시성 전략은 `09-testing-strategy.md` 참조).
- **AC1**: 상태 전이는 정의된 경로만 허용된다(예: `승인완료`에서 `진행중`으로 되돌릴 수 없다).
- **AC2**: 같은 단계 병렬 결재자의 동시 승인, 승인과 회수의 동시 요청에서 상태가 일관되게 유지된다(레이스에서 한 전이만 적용).

### AP-034 서명 필수
- **모든 결재 승인 행위에 키 서명을 요구**한다(FND-008).
- **AC1**: 서명 없이 승인 처리되지 않는다.
- 편의: 한 세션에서 키를 한 번 로드해 연속 서명 가능하도록 구현(보안 저하 없이). 상세 `10-nonfunctional.md`.

## 5. 결재 양식 (고정 양식 4종)

양식은 코드로 정의(폼 빌더 없음). 새 양식 추가 시 코드 수정·배포 필요. 공통 헤더: 제목, 작성자, 작성일, 소속 부서. 모든 양식은 **파일 첨부** 가능(AP-040).

### AP-040 첨부
- 결재 문서에 파일 첨부 가능. 저장은 MinIO 경유(백엔드 업로드/다운로드, 권한 검사).
- **AC1**: 첨부 파일은 MinIO에 저장되고 메타데이터(파일명·크기·업로더·문서ID)가 DB에 기록된다.

### AP-041 지출결의서
- 다중 행 지출 내역 테이블 + 푸터.
- 행 칸: 항목명(적요), 수량, 단가, **금액(수량×단가 자동, 수정 불가)**, 비고.
- 푸터: 합계(행 금액 자동 합산), 지출 예정일/집행일, 거래처/수취인.
- 단가 없는 일괄 비용은 "수량 1 + 단가에 전체 금액" 규칙으로 입력.
- **AC1**: 금액 = 수량 × 단가로 계산되며 직접 수정할 수 없다.
- **AC2**: 합계는 모든 행 금액의 합과 일치한다.

### AP-042 휴가·근태 신청서
- 필드: 휴가 종류(연차/반차[오전·오후]/병가/경조사/공가/기타), 기간(시작~종료), 반차 구분, **총 일수(자동 계산)**, 사유, 업무 대행자(임직원 선택).
- 일수 계산: **영업일 기준**(토·일·공휴일 제외). 반차=0.5일, 단일 날짜만.
- 공휴일은 관리자가 등록(AP-043). 미등록 공휴일은 영업일로 간주.
- 연차 잔여 차감은 범위 외(일수 산출까지만).
- **AC1**: 기간 내 토·일·공휴일은 총 일수에서 제외된다.
- **AC2**: 반차는 0.5일로 계산되고 단일 날짜에만 허용된다.
- **AC3**: 공휴일로 등록된 날짜는 일수에서 제외된다.
- **AC4**: 종료일이 시작일보다 빠르면 거부된다.

### AP-043 공휴일 관리
- 시스템 관리자가 연도별 공휴일(날짜·명칭)을 등록·수정·삭제한다.
- **AC1**: 등록된 공휴일은 휴가 일수 계산에 즉시 반영된다.

### AP-044 비품 신청서
- 다중 행: 비품명, 수량, 예상 단가, 금액(자동), 비고 + 합계.
- 추가: 희망 수령일, **수령 거점(거점 선택)**, 신청 사유.
- 재고 자동 차감 없음(수동 운영, AST 참조).
- **AC1**: 수령 거점 선택지에 비활성 거점은 표시되지 않는다.

### AP-045 일반 품의서
- 제목 + 자유 본문(서식 텍스트). 구조화 필드 없음.
- **AC1**: 본문 없이 상신 시 거부된다(최소 입력 검증).

## 모듈화 가이드 (TDD)
- **결재 흐름 엔진**을 순수 도메인 서비스로 분리: 입력=`(결재선 스냅샷, 현재 진행상태, 액션[승인/반려/합의거부])`, 출력=`다음 진행상태`. DB·프레임워크 비의존 → 표 기반 단위 테스트로 모든 흐름(순차/병렬/합의/전결) 검증.
- **휴가 일수 계산기**를 순수 함수로 분리: 입력=`(시작일, 종료일, 반차여부, 공휴일 목록)`, 출력=`일수`. 경계값 테스트(주말 시작/종료, 공휴일 포함, 단일일 반차).
- **전결 결재선 생성기**를 순수 함수로: 입력=`(기본 결재선, 양식의 전결 단계)`, 출력=`잘린 결재선`.
- 서명 검증은 FND `signature` 서비스 재사용.
