# 04. 비품 관리 (AST)

거점에 종속. 개체 관리 + 수량 관리 혼합 모델. 모듈 코드: **AST**

---

### AST-001 관리 단위 구분 (혼합)
- 비품 등록 시 비품관리자가 해당 품목을 **개체 관리** 또는 **수량 관리**로 직접 지정한다(금액 자동 구분 없음).
- **AC1**: 등록 시 관리 유형을 명시해야 한다(미지정 거부).
- **AC2**: 등록 후 관리 유형 변경 정책은 1차 범위 외(변경 불가로 구현).

### AST-002 개체 관리 비품
- 속성: 거점, 관리번호(고유), 상태(사용중/보관/수리/폐기), 취득일, 사진(개체마다 다중), 품목명.
- **상태 변경 이력은 남기지 않는다**(현재 상태만 보관, 덮어쓰기).
- **AC1**: 관리번호는 중복 불가.
- **AC2**: 상태를 변경하면 현재 상태만 갱신되고 과정 이력은 저장되지 않는다.
- **AC3**: 사진은 개체 단위로 다중 등록된다.

### AST-003 수량 관리 비품
- 속성: 거점, 품목명, 현재 수량, 사진(품목마다 다중).
- **입·출고 이력을 기록**하여 누적 추적한다. 현재 수량은 입출고 이력의 합으로 산출.
- **AC1**: 입고/출고 등록 시 이력 레코드가 생성된다.
- **AC2**: 현재 수량 = (입고 합) − (출고 합)과 일치한다.
- **AC3**: 출고로 수량이 음수가 되는 처리는 거부된다.
- **AC4**: 사진은 품목 단위로 다중 등록된다.

### AST-004 폐기 처리
- 개체 비품을 폐기하면 레코드는 **삭제하지 않고 `폐기` 상태로 보존**(조회 가능).
- **AC1**: 폐기된 개체는 목록에서 제거되지 않고 `폐기` 상태로 조회된다.

### AST-005 사진 업로드 (PC)
- 비품 사진은 PC에서 파일 업로드. MinIO 경유 저장.
- **AC1**: 업로드된 사진은 MinIO에 저장되고 메타데이터가 DB에 기록된다.

### AST-006 결재 연동 없음
- 비품 신청서(AP-044) 승인과 재고는 **연동하지 않는다**(수동 운영). 승인돼도 재고 자동 차감 없음.
- **AC1**: 비품 신청 승인 이벤트가 재고 수량을 자동 변경하지 않는다.

---

## 데이터 모델 주의 (개체 vs 수량)
- 개체 비품: **상태 필드 덮어쓰기** 모델(이력 테이블 없음).
- 수량 비품: **입출고 트랜잭션 누적** 모델(이력 테이블 있음, 현재 수량은 파생).
- 두 유형을 하나의 추상 비품으로 묶되, 저장 전략이 다르므로 명확히 분리(상세 `11-data-model.md`).

## 모듈화 가이드 (TDD)
- `asset` 패키지. 수량 산출(`입출고 이력 → 현재 수량`)을 순수 함수로 분리해 테스트(음수 방지 경계값 포함).
- 개체/수량 분기 로직을 전략 패턴으로 분리하면 각 전략을 독립 테스트 가능.
